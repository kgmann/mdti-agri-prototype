# Integration

The contracts between the prototype and the outside world: what partners can call, which external services it calls, and which national systems a real deployment would connect to. Internal API routes used only by the portals are not listed here; they live next to their pages in `src/app/api/`.

## Partner API (v1)

This is the platform's public face for banks and other partners. The bank portal uses it too. All endpoints are read-only, return JSON, and require the shared login (basic auth). Only farmers who agreed to share their data with partners are returned. Farmers are identified by their NPI.

| Method and path | Returns |
|---|---|
| `GET /api/partner/v1/farmers` | Farmers ranked by credit score. Query parameters: `department`, `crop`, `min_score`, `limit`. Each item: NPI, name, commune, department, cultivated area, main crops, score, band, estimated income. |
| `GET /api/partner/v1/farmers/{npi}` | One farmer's profile: identity, cooperative, parcels (with areas), production history per campaign, input-credit repayment history, score with its factors, estimated income for the current campaign. |
| `GET /api/partner/v1/farmers/{npi}/parcels` | The farmer's parcels as a GeoJSON FeatureCollection. |
| `GET /api/partner/v1/banks/{id}/offers?limit=` | For a given bank: eligible farmers with the indicative lending ceiling computed from that bank's policy. |

Example:

```bash
curl -u "$BASIC_AUTH_USER:$BASIC_AUTH_PASSWORD" \
  "https://agriprototype.lucatakpa.com/api/partner/v1/farmers?department=Zou&min_score=60"
```

In a real deployment, each partner would have its own credentials and scopes, every access would be logged, and the service would be published on X-Road.

## External services used

- **Gemini API** (Google). Chat, image understanding and speech input use a multimodal model; speech output uses a text-to-speech model. Environment variables: `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_TTS_MODEL`. Only synthetic data is sent.
- **Open-Meteo** forecast API. Called server-side with the farm's coordinates to get current conditions and a 7-day forecast; responses are cached for an hour. No key needed. For non-commercial use only, which fits a prototype.
- **Basemaps.** OpenStreetMap tiles for the street map and Esri World Imagery for the satellite view, both with attribution.

## Datasets

- **Administrative boundaries:** [geoBoundaries](https://www.geoboundaries.org) for Bénin, departments (ADM1) and communes (ADM2), simplified versions, licence CC BY 4.0. Stored in `db/data/` and loaded by the seed script.
- **Everything else is synthetic** and generated by `scripts/seed.ts` from a fixed random seed, so every run produces the same data. See [misc notes](04-misc-notes.md#synthetic-data).

## National systems (not connected)

A real Agri-Digit Bénin would reuse what already exists instead of rebuilding it:

- **ANIP / RNPP (NPI).** The person identifier for farmers. Registration would verify the NPI against ANIP instead of creating a separate farmer ID.
- **DGI (IFU).** The identifier for organisations (cooperatives, processors, distributors, banks, insurers). DGI now issues an IFU to individuals from their NPI.
- **X-Road** (national interoperability platform). The natural channel to publish the partner API and to exchange data with other ministries' systems.
- **METEO-Bénin.** The authoritative source for weather data and alerts, instead of Open-Meteo.
- **Mobile money operators.** The rail for the "one-click payments" described in the terms of reference.
